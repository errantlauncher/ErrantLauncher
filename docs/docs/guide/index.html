Errant Launcher — User Guide

1. About this guide

What Errant Launcher is. It is a portable app for Windows that gathers cards for launching and opening frequently used items in one window: programs, scripts, folders, files, commands, links and MSI installers. Cards can be arranged into sections and categories. The app requires no installation; its folder can be carried around, for example on a flash drive.

How to use this guide. You can read it in order — starting from "Getting started" — or open the section you need when necessary. Links to related sections are provided throughout.

2. Getting started

2.1. First launch

Run the ErrantLauncher-x64.exe file. No installation is needed: the app is portable. Next to the file it will create its data folder — settings, cards and icons will be stored there (see the "Data storage" section for details).

If you launch the app again while it is already running, no second window is created. The existing window is brought to the front (or restored from the system tray).

2.2. What you see after opening

The main window consists of several areas:

  • top — the title bar with "minimize", "maximize/restore" and "close" buttons;
  • left — a sidebar with the "Favorites" item and the list of sections;
  • below the title — round category "pills" of the selected section;
  • top right — the "Search…" field, the "Editor", sorting and settings buttons;
  • center — the card grid;
  • bottom left — the status button that opens the info panel.

The bottom-right corner may show indicator labels: "Administrator mode" (the app is running as administrator), "Read-only" and "No media" (data folder problems — see the "Troubleshooting" section).

2.3. How data is organized — in simple terms

  • Card — a button in the grid that launches or opens a single thing: a program, folder, link, etc.
  • Category — a subgroup inside a section (the pills above the grid).
  • Section — the top grouping level (the list on the left).
  • Favorites — a separate view collecting marked cards from all sections.

2.4. First actions

  1. Open "Editor" → "Structure" tab → "Add section" and "Add category" — build the frame for your tasks.
  2. Return to the main window, select a section and a category.
  3. Add your first card — using any method from section 6.
  4. Customize the appearance via the settings button (theme, accent color).

2.5. How to create your first card

The fastest way — drag a program file (.exe) straight onto the Errant Launcher window: the card will appear in the current section and category. Second way: "Editor" → "Add card" → choose a type → fill in the fields → "Save". See section 6 for details.

3. Interface and navigation

3.1. Main window

The window can be dragged by a free area of the top bar. The buttons in the top-right corner minimize, maximize and close the window. If minimize-to-tray is enabled (see the "Settings" section), the "Close" button hides the window to the system tray instead of exiting the app.

3.2. Sidebar

The list on the left shows "Favorites" and all visible sections. Clicking a section selects it and shows its categories and cards. Clicking an empty area of the panel expands/collapses it; clicking the window background with the panel expanded collapses it back. Hidden sections are not shown here (see section 4).

Right-clicking a section opens a menu: "Rename", "Hide section", "Delete section". On a category pill: "Rename", "Hide".

3.3. Cards and their indicators

A card shows an icon, a name and may carry labels:

  • "Error" — the card's target is unavailable (file deleted, wrong path);
  • "Admin" — the card is set to run as administrator;
  • "Checking" — an availability check is in progress;
  • architecture labels on programs: x86, x64, ARM64, Any;
  • groups have a group mark (see section 8).

A left click launches/opens the card, a right click opens its menu. If the text does not fit, hover the cursor — a tooltip with the full text appears.

3.4. Search

Type text into the "Search…" field — the grid filters with a short delay. Search matches the card name, the target file name and the description; all words of the query must match. Esc in the search field clears it, keeping focus in the field. The clear button does the same.

Tip

While a search is active, the "Editor" button is unavailable — clear the search first.

3.5. Sorting

The sorting button in the toolbar opens a list of options: "No sorting", "By name", "By type", "By launch frequency". Frequency sorting uses each card's launch counter — the more often you launch it, the higher it rises.

3.6. Status info panel

The status button at the bottom left opens a panel with counters and indicators (administrator mode, storage mode, etc.). Pressing it again or Esc closes it. The panel and the settings window cannot be open at the same time — one closes the other.

3.7. System tray

If minimize-to-tray is enabled in settings:

  • the "close" button hides the window to the tray together with all open child windows (they return to their places on restore);
  • clicking the tray icon shows/hides the window;
  • the icon's menu: "Open" and "Exit";
  • "Exit" asks every window with unsaved changes for confirmation — for example, an editor with an unfilled form offers to save or discard edits.

If you disable minimize-to-tray while the window is hidden, it immediately returns to the screen.

4. Sections and categories

What for. Sections are large thematic groups ("Work", "Multimedia", "Tools"), categories are subgroups inside them ("Browsers", "Editors"). Each card lives in one category of one section.

Management — in the editor, "Structure" tab:

Action How to do it
Create a section "Add section" → enter a name
Create a category select a section → "Add category" → enter a name
Rename the rename button on the row, or the section menu in the sidebar
Reorder the "up"/"down" buttons on the section row
Hide/show the visibility button on the section or category row
Change a section icon the icon button on the section row → icon picker (section 11)
Delete the delete button on the row → confirmation

Rules: a name cannot be empty; section names and category names within a section must be unique — on a clash the app reports "already exists".

Hiding. A hidden section disappears from the sidebar together with all its categories; a hidden category disappears from the pills. No data is deleted: everything stays in the structure editor and comes back via the visibility toggle.

Warning

Important — deleting:

  • deleting a section irreversibly deletes all its categories and cards — the app warns about this in the confirmation dialog;
  • deleting a category deletes all its cards — also with a warning.

Order and visibility are saved automatically. If the write fails (for example, the storage is read-only), the app shows an error and re-reads the structure — see the "Troubleshooting" section.

5. Cards: core principles

A card is a launchable item in the grid. Nine types are supported: program, script, folder, file, Windows shortcut, command, URL/URI, MSI package and card group.

Common fields (in almost all types):

  • Name — required; shown on the card and in search;
  • Description — optional; also takes part in search;
  • Section and category — where to put the card;
  • Icon — can be chosen via the icon picker (section 11);
  • "Run as administrator" — where it makes sense (programs, scripts, commands, MSI).

Names may repeat. If the chosen category already has a card with that name, a hint appears — it is not an error and does not block saving.

Paths. Both relative paths (from the app folder — better for portability) and absolute ones (C:\…) are accepted. Absolute paths are accepted but may stop working after moving to another computer — see section "Data storage and portability".

Saving and cancelling. The "Save" button writes the card; it is inactive until the required fields are filled. When closing the editor with unsaved changes, the question "Discard unsaved changes?" appears — "Don't save" drops the edits.

6. Creating cards of different types

Two universal methods:

  1. Drag-and-drop — drag a file or folder onto the main window. The type is detected automatically (.exe → program, .lnk → shortcut, .msi → MSI, scripts → script, folder → folder, anything else → file). For programs and shortcuts the icon is extracted automatically. Cards land in the current section/category; if there are no sections yet, a service section for incoming items is created. You can also drag link text http:// or https:// — a URL card is created.
  2. Via the editor — "Editor" → "Add card" → choose a type → fill the form → "Save". If there are no sections/categories yet, a hint panel appears with buttons to create them.

After saving, the main window scrolls to the new card and highlights it.

6.1. Program

  • Purpose: launching .exe.
  • Fields: name, section/category, launch variants, arguments, working folder, icon, "as administrator".
  • Launch variants: a card can store several .exe files for different Windows architectures — x86, x64, ARM64. The "Browse…" button adds a file: the app detects the architecture itself and labels the row. Choosing the same architecture again replaces the path; each row can be deleted or edited manually.
  • Checks: at least one variant is required; the file must be an existing .exe; the working folder must be an existing directory.
  • On launch the variant matching your system is chosen (for example, on 64-bit Windows x64 first, then x86). The "Run x64" etc. menu items launch a specific variant.
Tip

You don't have to set the card icon manually — extract it from the chosen .exe via the icon picker.

6.2. Script

  • Purpose: launching script files (bat, ps1, reg, vbs and other supported formats).
  • Fields: name, script file, section/category, working folder, icon, "as administrator"; the script type is detected from the extension automatically.
  • Checks: the file is required, must exist and have a supported type.
  • On launch a confirmation is always asked — the script's name and description are shown before execution. For .reg — a separate warning that a registry file changes system settings.

6.3. Folder

  • Purpose: open a directory in Explorer.
  • Fields: name, folder path, section/category, icon.
  • Checks: the path must exist and point to a folder (if a file sits at the path — an error).

6.4. File

  • Purpose: open a document/media with the associated app.
  • Fields: name, file path, section/category, icon.
  • Checks: the file must exist; extensions that have their own card types (.exe, .lnk, .msi, scripts) are reserved — choose the matching type for them.

6.5. Windows shortcut

  • Purpose: launching an existing .lnk.
  • Fields: name, .lnk path, section/category, icon, "as administrator".
  • Checks: the path must end in .lnk and exist.

6.6. Command

  • Purpose: run a text command (as in the command line).
  • Fields: name, command text, section/category, "as administrator".
  • Checks: the command must not be empty.
  • On launch a confirmation dialog is shown. The "Copy command" menu item puts its text into the clipboard without executing.

6.7. URL / URI

  • Purpose: open a link in a browser or a handler app.
  • Fields: name, address, section/category, icon.
  • Checks: only safe schemes are allowed — known dangerous ones are rejected when saving. The "Copy link" menu item puts the address into the clipboard.

6.8. MSI package

  • Purpose: launching an .msi installer.
  • Fields: name, path to .msi (a browse button with an "MSI package" filter), installer arguments, icon, "as administrator".
  • Checks: the file must be .msi and exist. On launch the arguments are parsed: a broken string (an unclosed quote), a switch without a value or an argument pointing at another package produce an error message — then check the "Arguments" field.

6.9. Card group

A group launches several cards in sequence. Detailed instructions are in the "Card groups" section.

7. Launching and opening items

The main way to launch is a left click on a card. Additional actions are in the context menu (right click). Depending on the card type it may contain "Launch", launching a specific architecture variant, launching with elevated or normal rights, and actions for opening a folder, file, shortcut or link. The menu content depends on the card type.

Service actions in the card menu:

  • "Open location" — Explorer with the target file selected;
  • "Copy path", "Copy command", "Copy link" — to the clipboard;
  • favorites and editing — sections "Editing and organizing cards" and "Favorites".

Arguments and working folder (programs, scripts, MSI) are set in the card form. If the working folder is empty — the target's own folder is used.

Confirmations. Before scripts, commands and groups containing them, the app asks for confirmation — protection against accidental launches. For .reg — a special warning. If a launch requires administrator rights, Windows shows the standard UAC prompt: declining it simply cancels the launch with an error message.

Tip

If Errant Launcher itself runs as administrator (the "Administrator mode" label), the processes it launches also get elevated rights.

Typical launch errors are described in the "Troubleshooting" section.

8. Card groups

Purpose: one group card launches several cards in a row — for example, a "work environment": mail, browser, editor.

Creating: "Editor" → "Add card" → "Group" → the participant selection button opens a dialog listing all cards. It has search and filters by section and type; marks are kept while you filter the list. "OK"/Enter confirms the selection, Esc/"Cancel" dismisses it. A group must contain at least one member; nested groups are not allowed. Members can have individual delays before the next one launches.

Order: members run in the original order of the card list.

Launch and progress. If the group contains scripts or commands, a warning appears first. Then the "Launch group" dialog opens:

  • an "N of M" counter and the current member's name;
  • before the next one — a countdown "Next: … — in X s";
  • as it runs, lines "Card "…" — launched / cancelled / not launched" are added;
  • the "Cancel remaining" button, Esc or closing the window stops the queue — what has been launched is not rolled back.

Result: a summary "Launched: X · Errors: Y · Skipped: Z" with a line per card; on cancel — "Launch cancelled"; on errors — a dialog with the "error" kind.

Errors: a member whose target is gone is marked "not launched" with the reason — this does not bring down the rest of the queue. Deleted cards automatically disappear from groups.

9. Editing and organizing cards

Edit a card: card menu → "Edit" → the same form as at creation, with filled fields → "Save".

The card table — "Editor" → "Edit cards":

  • search in the table and "by type" / "by section" filters;
  • sorting — click a column header;
  • row checkboxes for multiselect; the "select all" / "clear selection" buttons act on the current filtered list;
  • "Edit" — only with a single row selected;
  • "Delete", "Move", "Duplicate" — with one or more rows selected.

Deleting: one card asks "Delete card?", several — "Delete cards?" with a counter. Deletion is irreversible: the card disappears from the section, favorites and all groups.

Move: a section and category picker dialog — the selected cards move there.

Duplicate: a copy in the same category.

10. Favorites

Add/remove: right-click a card → "Add to favorites" / "Remove from favorites".

Viewing: the "Favorites" item in the sidebar. Instead of category pills, type tabs appear here: "All", "Programs", "Scripts", "Folders", "Files", "Shortcuts", "Commands", "URL / URI", "MSI packages", "Groups" — favorites can be browsed by type. Search works here too (within favorites).

On import/export favorite marks travel together with the cards (on import — if the corresponding option is checked, see section "Import, export and backups").

11. Icons and appearance

11.1. Card and section icons

The card form and the structure editor have an icon picker button. The picker window offers:

  • the built-in type icon;
  • an icon from the built-in set — a selection grid (arrow keys and Enter/Space work inside the grid);
  • your own PNG file;
  • icon extraction from an .exe or .lnk — the "Extract" button;
  • "Reset" — return to the default.

"Save" applies the choice, "Cancel"/Esc does not. If extraction fails or the file is not a PNG — an error message appears, the previous icon is unaffected.

11.2. Application appearance

In settings (section 14): language, theme, accent color (it also recolors the tray icon), card icon style ("Theme colors" / "Accent color" / "Colorful") and label style. Changes apply immediately.

12. Mass import

What for. When you need to add not one card but a whole folder of programs — the wizard finds .exe, scripts, .msi, .lnk, files and subfolders itself, shows the list and lets you pick what to add.

Where: "Editor" → "Mass import" tab. The wizard walks through steps: "Choose folder" → "Scan" → "Results" → "Where to add" → summary.

12.1. "Choose folder" step and filters

  • Folder to scan — choose via "Browse folders…" or enter manually. A non-existent folder is highlighted with the message "Folder does not exist."
  • Traversal depth — "Unlimited" or 1–3 levels; "Recursive traversal of nested folders"; "Maximum candidates" — when the limit is reached, the scan stops (narrow the filters or increase the value).
  • Type pills — which types to look for. Some types have their own settings:
  • Programs — which architectures to include (including "Any" for unrecognized ones);
  • Scripts — which script types;
  • Files — a list of extensions separated by ";" in "Exclude listed" or "Search only listed" mode;
  • MSI and Shortcuts — no extra filters.
  • Traversal settings: skip hidden, system, junction points and symlinks; "Scan network paths (UNC)"; a list of excluded folder names.
  • Configuration folder — specify it if you want the app to check candidate path portability.

12.2. "Scan" step

Shows "Items viewed", "Candidates", "Warnings" and the current folder. The "Stop" button interrupts the scan — the found part is kept marked "scan interrupted". On error — a message and "Retry"/"Back" buttons. If the scan stopped on the limit, a mark appears — narrow the filters.

12.3. "Results" step

A table of found candidates with statuses: "ready", "check", "gone", "error", plus "already exists" and "cannot add" labels. Problem rows state the reason — for example, "file unavailable for reading", "duplicate: card already exists", "name already used in the target section", "network path disabled by filter".

Features:

  • search by name/path, filters by type and status, column sorting;
  • "Clear selection" / "Exclude selected" — for the current filtered list;
  • "Re-check" — rechecks the selected files on disk without a new scan: a file that came back can be restored;
  • an expanded row lets you edit the name, arguments, description, working folder, script type, icon and "as administrator";
  • the row menu — "Copy path" and "Show location in folder".

Candidates with errors and duplicates are excluded from selection automatically, but can be included manually.

Warning

If you change the folder or filters after scanning, the results become "stale" — the wizard suggests rescanning and warns that your edits will apply to the same files if they are found again.

12.4. "Where to add" step

  • Target section — an existing one or "New section…";
  • Category — an existing one, "New category…", "No category" or "By parent folder name" (candidates are sorted into categories automatically);
  • the "Check" button — analysis: "Will be added / Will skip / Need attention", lists of path duplicates, name conflicts and broken candidates; a note about drive-letter paths (they may not open on another computer).

Import is blocked if the storage does not accept writes (the message "Configuration is not available for writing"), no target is chosen, no candidate is checked or all selected ones have errors.

12.5. Import and summary

"Import N cards" starts writing in the background. A data backup is created before writing. The summary page shows "Added", "Skipped on import", "Not selected" and details — for example, how many cards were added without their own icon.

Warning

On a partial write or a failure the app reports it with separate messages and shows the backup path for manual rollback; until the state is acknowledged, repeating the import is paused — reopen the "Where to add" step for a recheck or restart the app.

Cancelling: on the scan step "Cancel" stops the scan; on other steps, leaving the wizard with unfinished work asks "Edits and selection will be lost — leave?". Closing the editor with an unfinished import also asks for confirmation — background tasks are stopped cleanly.

13. Import, export and backups

Where: the settings button → "Import" / "Export" / "Reset all data".

13.1. Export types

  1. Full backup — everything at once: sections, cards, favorites, settings, themes, icons and application state. No content selection windows — straight to "Save as" with the name ErrantLauncher-Backup.zip. Use it for backups and moving between computers.
  2. Share collection — content selection: "Icons" and "Themes" checkboxes and a list of sections (with "Select all"). Settings and state are not included; favorites travel with the cards. The file name is ErrantLauncher-Collection.zip.
Warning

If the checked sections contain groups referencing cards of unchecked sections, a warning appears — you can continue or cancel and adjust the marks.

On completion it shows what exactly was exported, with a button to open the file's folder.

13.2. Import

  1. "Import" → choose a .zip.
  2. A warning that the import will change data — "Continue"/"Cancel".
  3. A selection window: "Settings", "Favorites", "Icons", "Themes" checkboxes (only what exists in the archive) and the archive's section list.
  4. If section names match existing ones — a conflict window: for each section "Replace / Rename / Skip", and the choice can be applied to all.
  5. A result dialog.

A backup snapshot is made before writing — on error the data is rolled back. A full backup with "Settings" checked also restores the application state.

Errors: a non-zip or broken file — "invalid import file"; an archive newer than the app version — "newer format"; cancelling at any step imports nothing; invalid theme files are skipped and listed in the summary.

Tip

Before moving: make a full backup at the old location and check that the file opens as an archive.

15. Data storage and portability

Where data lives. The app is portable: its data folder sits next to the executable. Inside — settings files, section files with cards (sections/*.json), the custom icons folder (custom-icons/), backups (.backup/, .rollback/) and the logs/app.log log.

Card paths. The app tries to store relative paths — that way the setup survives being moved to another drive/computer together with the data folder and target files. Absolute paths (C:\…) are accepted but only work where they are valid.

Moving. Copy the whole app folder — the exe, data and preferably the target files. Before moving, make a full backup (section "Import, export and backups").

Removable drive — a normal scenario. If a flash drive is removed while the app is running, it switches to "No media" mode: on-screen data stays, but writing becomes impossible. When the drive returns, writing is restored automatically on the next save attempt — the app checks that its own data root came back.

Storage modes:

Indicator What it means Consequences
(none) everything is fine read and write
"Read-only" data is readable, writing is impossible the editor and mutations are closed; settings apply until restart
"No media" the data root is unavailable writes are rejected with an error message

Manual file editing. sections/*.json files can be edited in a text editor while the app is closed; with the app running, external edits are picked up only after a restart. A broken file does not crash the app — at startup an "Keep/Delete" dialog appears for each damaged file (deleting makes a backup copy). If two files declare the same section, their contents are merged — a notification reports this.

17. Troubleshooting

A card does not launch, "Error" label. The target is unavailable: the file/folder was deleted or the path is wrong. Menu → If the target exists, "Open location" helps you reach it. If the path is wrong or the object is deleted, open the card menu → "Edit", fix the path and save the changes, or recreate the card.

Error when launching with elevated rights. Declining the UAC prompt cancels the launch — repeat and confirm, or remove "as administrator" from the card.

Data is not saved, "Read-only" indicator. The storage is opened read-only: check that the app folder and data files are not marked with the "read-only" attribute, that write permissions exist and there is free space. The editor and changes stay unavailable until writing is restored.

"No media" indicator. The data folder is gone (removed flash drive, renamed folder, unavailable network path). Bring the drive/folder back — writing is restored on the next save attempt. A renamed empty folder will not "reattach": the app only accepts its real data root.

"Keep/Delete" dialog at startup. A configuration file is corrupt. "Keep" — the file is untouched (you can fix it manually; the dialog repeats on the next launch); "Delete" — the file is deleted with a backup copy. In "Read-only" mode there is no "Delete" button.

"Data created by a newer version" warning. The files were written by a newer Errant Launcher; the old version will not overwrite them. Update the app to that or a newer version.

Cannot get an icon. Extraction from .exe/.lnk failed or the file is not a PNG — choose another source or a built-in icon.

Import finished with an error or partially. Read the result text: it states what was written, which files were changed and where the rollback backup is. If you get a message about a paused re-import, reopen the "Where to add" step or restart the app.

A command or link does not open. For a command, check its text ("Copy command" → paste into the command line and test manually). For a link — that the scheme is allowed and a handler exists in the system; check the internet.

The app does not let me into the editor / settings are not saved. See the "Read-only" and "No media" items.

18. Resetting and restoring data

Warning

Reset is irreversible. "Reset all data" deletes all sections, categories, cards, favorites, settings and state — the app restarts clean.

How to do it: settings → "Reset all data" → go through two consecutive confirmation dialogs. Cancelling at any step aborts the reset; an error produces a message without a restart.

Preparation: before resetting, make a "Full backup" (section "Import, export and backups") — it is the only standard way to get everything back.

Restoring: "Import" → choose the backup file → check "Settings" and the types you need → resolve name conflicts → result. After restoring, check: did sections and cards appear, do the paths work ("Error" labels), did favorites and settings come back.

The "About" button in settings opens a window with the name, version, copyright and card statistics by type. Inside:

  • "Support the project";
  • links "Official website", "GitHub releases", "Documentation", "Report a bug" — they open in the browser.

20.3. Fields and parameters

  • Name — required, duplicates allowed (a warning hint).
  • Description — free text, takes part in search and in the script launch confirmation.
  • Working folder — the directory the process starts from; empty = the target's folder.
  • Arguments — launch parameters (programs, MSI); for MSI they are parsed per msiexec rules.
  • As administrator — elevated launch via UAC.
  • Group member delay — a pause before launching the next one.

20.5. Glossary

  • Card — a launchable grid element.
  • Section / category — the card grouping levels.
  • Favorites — a view with marked cards of all sections.
  • Launch variant — an .exe of a specific architecture in a program card.
  • Candidate — an object found by the mass import wizard.
  • Backup / collection — the two export kinds (everything / selected without settings).
  • Read-only / No media — degraded storage modes.

20.6. Frequently asked questions

  • Why can't I open the editor? The storage is in "Read-only"/"No media" mode or a search is active — clear the search field or restore writing.
  • Why does the window hide to the tray instead of closing? "Minimize to tray" is enabled — exit via the icon menu "Exit" or disable the setting.
  • A section disappeared. It is hidden — re-enable it in the structure editor.
  • How many cards can be imported at once? As many as the scan finds within the "Maximum candidates" limit.
  • Can I keep the app on a flash drive? Yes — that is what makes it portable; removing it mid-run switches to "No media".
