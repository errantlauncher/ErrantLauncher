Errant Launcher — User Guide

1. Getting to Know Errant Launcher

Errant Launcher is a portable Windows application. It brings together, in a single window, cards that launch everything you use often: applications, scripts, folders, files, commands, links, shortcuts, and MSI installers.

No installation is required: simply extract the ZIP archive and run the executable. The application folder can be moved — for example, kept on a USB drive and launched on any computer running a compatible system (see System Requirements: Windows 10 version 1607 or later, 64-bit).

Cards can be organized into sections and categories, marked as favorites, searched, and launched individually or in groups.

How to read this guide. You can read it in order — from first launch to advanced features — or open only the chapter you need: each stands on its own, with links to related topics.

Notation: button and menu names appear in quotes ("Editor", "Save"). A block marked "Important" warns about actions that cannot be undone. A block marked "Tip" offers a convenience hint.

2. First Launch

  1. Download the ZIP archive from the download page and extract it to any folder with write access — a USB drive works too.
  2. Make sure ErrantLauncher-x64.exe, libSkiaSharp.dll, and av_libglesv2.dll are together in the same folder — the app will not start without both DLLs.
  3. Run ErrantLauncher-x64.exe. An ErrantLauncher data folder will appear next to it — your cards and settings live there (details in Chapter 10).

On first launch, Windows SmartScreen may warn about an unknown publisher — the file is not code-signed. Choose "More info" → "Run anyway".

If the app is already running, a second instance is not created — the existing window opens (or is restored from the tray).

3. The Main Window

After launch you will see:

  • the title bar on top — drag the window by its free area; the buttons on the right minimize, maximize, and close;
  • the side panel on the left — "Favorites" and the list of sections;
  • category "pills" under the title — the categories of the selected section;
  • the toolbar on the top right — the "Search…" field, and the "Editor", sort, and settings buttons;
  • the card grid in the center;
  • the status button at the bottom left — opens an info panel with counters and indicators.

Badges may appear at the bottom right: "Admin mode" (the app is running elevated), "Read-only" and "No storage" (data folder problems — see Chapter 10).

Clicking empty space on the side panel collapses/expands it. Right-clicking a section opens a menu: "Rename", "Hide section", "Delete section"; right-clicking a category pill: "Rename", "Hide".

Search. Type into "Search…" — the grid filters. It searches card names, target file names, and descriptions; all words must match. Esc inside the field clears it. While a search is active, the "Editor" is unavailable — clear the search first.

Sorting. The sort button offers: "Custom order", "By name", "By type", "By launch frequency". The last option moves the cards you launch most often to the top.

System tray. If "Minimize to tray" is enabled in settings, the close button hides the window to the notification area instead of exiting. Clicking the icon brings the window back; its menu offers "Open" and "Exit". If you disable the setting while the window is hidden, it returns to the screen.

4. Your First Cards

Four terms you will need:

  • Card — a grid button that launches one item.
  • Category — a subgroup inside a section (the pills above the grid).
  • Section — the top grouping level (the list on the left).
  • Favorites — a separate view of marked cards from all sections.

Three ways to add a card:

  1. Drag and drop. Drag a file or folder onto the window — the type is detected automatically (.exe → program, .lnk → shortcut, .msi → MSI, script → script, folder → folder, anything else → file). You can also drag an http(s):// link — a URL card is created.
  2. Editor. "Editor" → "Add card" → choose a type → fill in the fields → "Save".
  3. Bulk import. To add an entire folder of items at once — see Chapter 8.

The card appears in the current section and category. If no sections exist yet, a service section is created for incoming cards.

Suggested start: "Editor" → "Structure" tab → "Add section" and "Add category" → return to the main window, select them → add your first card.

5. Cards in Detail

Common Fields

  • Name — required; shown on the card and searchable.
  • Description — optional; also searched.
  • Section and category — where the card belongs.
  • Icon — chosen via the icon picker (Chapter 9).
  • "Run as administrator" — where it makes sense (program, script, command, shortcut, MSI).

Duplicate names are allowed — the app shows a hint about the match but does not block saving.

Paths. Both relative paths (from the app folder — better for portability) and absolute paths (C:\…) are accepted. Absolute paths may stop working on another computer — see Chapter 10.

The "Save" button activates only when required fields are filled. Closing the editor with unsaved changes asks "Discard unsaved changes?".

5.1. Program

Launches an .exe. Fields: name, launch variants, arguments, working directory, icon, "run as administrator".

Launch variants — a card can hold several .exe files for different Windows architectures (x86, x64, ARM64). "Browse…" adds a file; the app detects the architecture and labels the row. Choosing the same architecture again replaces the path. At launch, the variant matching your system is used; the card menu can launch a specific one ("Run x64", etc.).

Checks: at least one variant is required, the .exe file must exist, and the working directory must be an existing folder.

5.2. Script

Runs script files (bat, ps1, reg, vbs, and others — the type is detected by extension). Fields: name, file, working directory, icon, "run as administrator".

A confirmation dialog always appears when you launch a script — the script's name and description are shown. For .reg, a separate warning about registry changes appears.

5.3. Folder

Opens a directory in File Explorer. Fields: name, folder path, icon. The path must exist and point to a folder.

5.4. File

Opens a document/media with its associated application. Fields: name, path, icon. The file must exist; extensions with their own card types (.exe, .lnk, .msi, scripts) are reserved.

5.5. Windows Shortcut

Launches an existing .lnk. Fields: name, path to the .lnk, icon, "run as administrator". The file must end in .lnk and exist.

5.6. Command

Runs a text command (as in the command line). Fields: name, command text, "run as administrator".

At launch a confirmation dialog appears; after the command finishes, the console window stays open so you can read the output — close it manually. The "Copy command" menu item puts the text in the clipboard without running it.

5.7. URL / URI

Opens a link in the browser or handler app. Fields: name, address, icon. Only safe schemes are accepted — dangerous ones are rejected. "Copy link" puts the address in the clipboard.

5.8. MSI Package

Runs a .msi installer. Fields: name, path (browse with an "MSI package" filter), installer arguments, icon, "run as administrator". An invalid argument string (for example, an unclosed quotation mark, a switch without a value, or an argument that points to another package) triggers an error. Check the "Arguments" field.

5.9. Card Group

Launches several cards in sequence. Creation and launching are covered in Chapter 6.

6. Launching and Working with Cards

Basic launch — left-click the card. Card menu — right-click; contents depend on the type: "Launch", launch a specific architecture variant, launch with or without elevation, "Open location" (Explorer with the file selected), "Copy path/command/link", "Edit", "Add to favorites", "Delete".

Confirmations — before scripts, commands, and groups containing them, the app asks for confirmation: protection against accidental launches.

Running as administrator. A card can have "Run as administrator" enabled — Windows then shows a UAC prompt; declining simply cancels the launch. If Errant Launcher itself runs elevated (the "Admin mode" badge), all applicable cards launch elevated automatically — regardless of their checkbox — and the "Admin" badge appears on all such cards. This does not apply to folders and links — they open normally. Recommendation: run the launcher with normal rights and elevate only the cards that need it.

Card groups. Created in the Editor → "Group" → pick members from the list (with search and filters). A group must have at least one member; nested groups are not allowed. Members can have an individual delay before the next launch. At launch, the "Group launch" dialog opens: an "N of M" counter, a "Next: … — in X s" countdown, and "launched / cancelled / not launched" rows. "Cancel remaining" or Esc stops the queue — what has already launched is not rolled back. Summary: "Launched: X · Errors: Y · Skipped: Z".

Arguments and working directory (program, script, MSI) are set in the card form; an empty working directory means the target's own folder.

7. Organizing Your Collection

Sections and categories are managed in the Editor → "Structure": "Add section" / "Add category", rename, order ("up"/"down"), hiding (visibility toggle), changing a section icon, deleting.

Rules: names cannot be empty and must be unique within their level — on a duplicate the app reports "already exists". A hidden section disappears from the side panel, a hidden category from the pills; nothing is deleted and they return when unhidden.

Important — deleting: deleting a section permanently deletes all its categories and cards; deleting a category deletes all its cards. The app warns you in a confirmation dialog.

Favorites. Right-click a card → "Add to favorites" / "Remove from favorites". The "Favorites" item in the side panel opens a view with type tabs ("All", "Programs", "Scripts"…). Search works here too. Favorite status is preserved when cards are exported or imported.

Working with cards. "Edit" in the card menu opens its form. "Editor" → "Edit cards" — a table of all cards: search, filters by type and section, column sorting, multi-select, "Move" (to another category), "Duplicate", "Delete". Deletion is permanent — the card disappears from the section, favorites, and all groups.

8. Bulk Import

To add an entire folder of items at once: "Editor" → "Bulk import" tab. Wizard steps: "Select folder" → "Scanning" → "Results" → "Where to add" → summary.

Filters: traversal depth (unlimited or 1–3 levels), recursion, a "Maximum candidates" limit, type pills (programs — with architecture selection, scripts — with type selection, files — with an include/exclude extension list, MSI and shortcuts — without extra filters), skipping hidden/system/junction entries, "Scan network paths (UNC)", and excluded folder names.

Scanning shows counters: "Objects scanned", "Candidates", "Warnings". "Stop" aborts the scan — everything found is kept.

Results — a table with statuses ("ready", "check", "missing", "error") and labels ("already exists", "cannot add") with reasons. Options: search, filters, "Recheck" for selected files without a new scan, expanding a row to edit fields, "Deselect"/"Exclude selected". Candidates with errors and duplicates are excluded automatically — but can be re-enabled manually.

"Where to add": section — an existing one or "New section…"; category — existing, "New category…", "No category", or "By parent folder name". The "Check" button shows an analysis: "Will be added / Skipped / Needs attention", name conflicts, and a warning about drive-letter paths.

"Import N cards" — writes in the background; a verified backup snapshot is created automatically beforehand. Summary: "Added", "Skipped during import", "Not selected". On a partial write or failure, the app points to the backup path for manual rollback.

9. Appearance and Settings

Settings open via the button at the top right — a panel appears over the window; Esc closes it.

Appearance

  • Theme — the window's color theme.
  • Accent color — the interface accent and tray icon color.
  • Card icon style — "Theme colors" / "Accent color" / "Multicolored".
  • Badge style — the look of card indicators.

Behavior

  • Initial section — which section opens at startup.
  • Minimize to tray — closing hides the window to the tray instead of exiting (Chapter 3).

Language

  • Language — the interface language, 6 options.

All changes apply immediately and save automatically. In "Read-only" mode, settings apply until the app closes but are not saved.

Card and section icons — the icon button in the card form and in "Structure": built-in type icon, a collection of built-in icons, your own PNG, "Extract" from an .exe/.lnk, "Reset". If extraction fails or the file is not a PNG, an error appears and the icon stays unchanged.

The same panel holds "Import", "Export", "Delete all data", and "About" (version, card statistics, licenses, links to the site and GitHub).

10. Data Storage, Moving, and Backups

Where data lives. The ErrantLauncher folder next to the executable: section files with cards (sections\), settings (settings.json), app state (state.json), your icons (custom-icons\), logs (logs\), and service backups. Everything in one place — that is what makes the app portable.

Card paths. Relative paths survive moving with the app; absolute ones (D:\Tools\app.exe) work only where that path exists — on another computer with a different drive letter such a card shows "Error". The data folder itself is not tied to a drive letter.

Moving to another computer — copy everything: ErrantLauncher-x64.exe + both DLLs + the ErrantLauncher folder. Run it — your collection and settings are there. Make a full backup before moving.

Two export modes (settings → "Export"):

  • Full backup — everything: sections, icons, settings, and app state. ErrantLauncher-Backup.zip.
  • Share collection — selected sections, icons, and favorites, without settings. ErrantLauncher-Collection.zip.

Import (settings → "Import"): pick a .zip → confirm → check the data you want → if section names collide, choose "Replace / Rename / Skip". A backup snapshot is made before writing — on failure your data is rolled back.

USB drive. Supported. Removing the drive while the app runs switches it to "No storage" mode: data stays on screen, changes are held in memory and will be saved if the drive returns before the app closes. "Read-only" mode — when writing is impossible: cards remain visible and launchable, but changes apply only until the app closes.

A detailed description of the folder layout and backup mechanisms is on the "Data, backups and portability" page.

11. Resetting and Restoring Data

Restoring from a backup

From an exported file: settings → "Import" → pick ErrantLauncher-Backup.zip → check "Settings" and the data you need → resolve conflicts → verify the result.

From a folder copy: close the app, set the current ErrantLauncher folder aside just in case, restore the backup contents to their original location, and start the app.

Restoring a Data Folder

The ErrantLauncher folder can be moved and returned as a single unit — all cards, settings, and icons come back with it. Always replace it while the app is closed, and keep a copy of the folder you replace until you have checked the result.

Deleting all data

Important — this action is irreversible. "Delete all data" removes all sections, categories, cards, favorites, settings, and state — the app restarts empty.

Settings → "Delete all data" → two consecutive confirmation dialogs. Before resetting, save your data: a full backup via export or a copy of the ErrantLauncher folder — either lets you bring the collection back later.
