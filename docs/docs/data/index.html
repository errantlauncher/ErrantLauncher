Data, Backups, and Portability

Errant Launcher is a portable application. User data is stored in an ErrantLauncher folder alongside the executable. This page explains where data is stored, how to create backups, how to move your collection between computers, and how to restore data when needed.

Where Data Is Stored

When you first launch the application, it creates an ErrantLauncher folder next to the executable. For example, if the application is located in D:\Tools\, its data will be stored in D:\Tools\ErrantLauncher\.

The application does not write data to the Windows Registry or user profile folders such as Documents or AppData. Your collection, settings, and application data are stored in the data folder alongside the executable.

Data Folder Contents

PathContents
ErrantLauncher\sections\*.jsonSections, categories, and cards, stored in a separate file for each section
ErrantLauncher\settings.jsonAppearance and behavior settings, including theme, language, system tray options, and other preferences
ErrantLauncher\state.jsonWindow state, the last opened section, and launch counters
ErrantLauncher\custom-icons\Icons you have added or extracted from applications
ErrantLauncher\logs\Local diagnostic logs, including app.log and bootstrap.log
ErrantLauncher\.backup\A backup of the most recently deleted section
ErrantLauncher\.mass-import-backups\The latest backup created before a bulk import
ErrantLauncher\.import-staging\Temporary data used during imports

The .backup, .mass-import-backups, and .import-staging directories are used for internal operations. A leading dot does not make a directory hidden in Windows. Avoid deleting their contents unless necessary.

Backing Up Your Data

Errant Launcher supports configuration exports and creates internal backups before certain operations. These mechanisms serve different purposes and should not be treated as interchangeable.

1. Full Backup

Open Settings → Export Configuration and select the full backup option.

A full backup includes:

  • Sections and cards
  • Custom icons
  • Application settings
  • Application state

The suggested filename is ErrantLauncher-Backup.zip.

This is the recommended way to preserve your data before updating the application, moving it to another computer, or making major changes to your collection.

2. Share Collection

Open Settings → Export Configuration and select Share Collection.

This option is intended for transferring your collection and includes:

  • Selected sections and cards
  • Associated icons
  • Favorites data

Application settings and state are not included.

The suggested filename is ErrantLauncher-Collection.zip.

3. Internal Backups

The application uses two directories to store internal backups.

.backup\ — Backup of the Most Recently Deleted Section

Before deleting a section file, the application creates a backup of it. Only the most recent backup is retained; creating a new one replaces the previous backup. This is not a full collection backup or a general-purpose backup system.

.mass-import-backups\ — Backup Before a Bulk Import

Before a bulk import, the application creates a backup of sections, settings, application state, and custom icons. After the backup is created, its integrity is verified using SHA-256.

The application deletes previous bulk-import backups only after the new backup has been created and verified successfully. As a result, only the latest successfully created and verified backup is retained, preventing these backup directories from accumulating indefinitely.

If creating or verifying a new backup fails, the previous backup is not deleted. If an old backup cannot be deleted, the cleanup error should not, by itself, interrupt the import.

This backup is intended to help recover data if problems occur during a bulk import. It does not replace exporting a full backup to a separate, safe location.

Moving to Another Computer

Method 1: Move the Application and All Its Data

  1. Close Errant Launcher.
  2. Copy the application files, including ErrantLauncher-x64.exe, libSkiaSharp.dll, and av_libglesv2.dll.
  3. Copy the entire ErrantLauncher user data folder.
  4. Place the files on the new computer in a location where the application has the necessary write permissions.
  5. Launch ErrantLauncher-x64.exe.
  6. Check that your collection, settings, and icons are available.

Before moving the application, we recommend creating a full backup using Export Configuration.

The executable and required DLL files must remain together. Copying the entire data folder also preserves logs and any existing internal backups.

Method 2: Move Only Your Collection

  1. On the original computer, open Settings → Export Configuration.
  2. Select Share Collection and save the archive.
  3. On the other computer, open Import Configuration.
  4. Select the archive and choose which data to import.

This method is intended for transferring selected collection data. Settings and application state are not included in a Share Collection archive.

Import supports ZIP archives, individual JSON files, and configuration folders.

Important Notes About File Paths

Cards may contain absolute paths to applications and files, such as D:\Tools\app.exe. After moving the application, these cards will work only if the referenced files are available at the specified paths.

If the drive letter changes or a file is located in a different folder on the new computer, you will need to update the path. The bulk import wizard warns about cards with non-portable paths.

The launcher's own data folder is resolved relative to the executable's location. Its location is therefore not tied to a specific drive letter, although paths stored inside cards may be.

Updating Without Losing Data

Automatic updates are not available. You can update the application manually:

  1. Close Errant Launcher.
  2. Create a full backup using Export Configuration.
  3. Download the latest Windows x64 ZIP package and extract it to a temporary folder.
  4. Replace the application files with the files from the new package. The executable and required DLL files must remain together.
  5. Keep your existing ErrantLauncher data folder. Do not delete or overwrite it unless you intend to reset your collection and settings.
  6. Launch ErrantLauncher-x64.exe and verify that your collection is available.

Do not update the application by replacing only the EXE file. The DLL files included in the package are also required.

Before Reinstalling or Uninstalling

  • To keep your data, copy the entire ErrantLauncher folder. If you do not need logs or internal backups, at minimum preserve sections\, settings.json, and custom-icons\.
  • To remove the application, delete the EXE file and the ErrantLauncher data folder. The project does not write to the Windows Registry or user profile folders.
  • The current Native AOT version does not create %TEMP%\.net\ErrantLauncher. A directory from an older version may remain and can be deleted manually if it is no longer in use.
  • The Delete All Data option in Settings requires two confirmations and deletes the contents of the data folder, including logs and backups. The operation may fail if the storage device is unavailable.

Before deleting data, make sure you no longer need the backup.

If Files Are Inaccessible

The application handles access problems and damaged data as follows.

SituationBehavior
The data folder is read-onlyThe application switches to read-only mode. Cards remain available for viewing and launching, but changes are not saved to disk. Some changes may apply only for the current session
The storage device is temporarily unavailableA No storage indicator appears. Changes may remain in memory until the device is reconnected. If you close the application before access is restored, unsaved changes may be lost
The data folder is completely inaccessibleThe app displays a message indicating that the storage is unavailable, then closes.
An individual data file is corruptedA File Corrupted dialog appears. The file is not modified automatically; you can choose whether to delete it or keep it
A file was created by a newer application versionThe file can be read but is not overwritten. Updating the application is recommended
Multiple files are found for the same sectionCards are merged. Section metadata, including the icon and hidden status, is taken from the first file

If you encounter an error, do not delete data files or internal backups before creating an accessible backup.

Restoring from a Backup

From an Exported File

  1. Open Settings → Import Configuration.
  2. Select the backup file.
  3. Select the available data categories you want to restore.
  4. Complete the import and verify the result.

From a Folder Backup

  1. Close the application.
  2. Save the current ErrantLauncher folder to a separate location in case you need to restore its contents later.
  3. Restore the data folder from your backup.
  4. Launch the application and check your collection and settings.

After a Failed Bulk Import

Before a bulk import, the application creates a backup in .mass-import-backups\. The new backup is verified before the previous one is deleted, so the previous backup is retained if creation of the new one fails.

After a new backup has been created successfully, it replaces the previous backup. The directory therefore contains only the latest bulk-import backup.

If recovery is needed, locate the saved backup and follow the application's messages. Before restoring files manually, close Errant Launcher and save the current data folder separately. Copying a backup over the current data may overwrite newer changes.

Using USB Drives

Errant Launcher can be run from a USB drive. Its data folder is located alongside the executable, allowing you to move the application together with your collection and settings.

If the drive is removed while the application is running, access to the data may be lost. If the No storage status appears, reconnect the drive and wait for access to be restored.

Changes that exist only in memory may be written to the drive after access is restored. However, if you close the application or it crashes before the drive is reconnected, those changes may be lost.

Also note that cards using absolute file paths may not work on another computer, even if the launcher and its data folder have been transferred correctly.
