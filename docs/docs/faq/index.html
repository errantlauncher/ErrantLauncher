Frequently Asked Questions

Answers to common questions and solutions to typical problems with Errant Launcher. Detailed instructions: Data and Portability, System Requirements, and Support.

The app won't start

  • Check system compatibility: Windows 10 (1607) or later, 64-bit. See system requirements.
  • Make sure both DLLs are next to ErrantLauncher-x64.exe: libSkiaSharp.dll and av_libglesv2.dll. The app won't start without them.
  • Verify the app has write access to its folder — it cannot create the data folder otherwise.
  • If nothing happens, check ErrantLauncher\logs\bootstrap.log and app.log — startup errors are recorded there.

Windows SmartScreen warns about an unknown publisher

Expected behavior: the executable is not signed with a code-signing certificate. Choose More info → Run anyway. Before launching, you can verify the file's checksum against the one published on the download page or in the archive's SHA256SUMS.txt.

Do I need .NET installed?

No. The app is built with Native AOT — the runtime is embedded in the executable. No separate .NET installation is required.

"Errant Launcher is already running"

Only one instance can run at a time. If no window is visible, check the system tray — the app may be minimized there. If a stale process remains in memory, end it via Task Manager and relaunch.

How do I add cards?

Three ways:

  • Drag and drop a file, folder, or shortcut onto the launcher window.
  • Editor — add sections, categories, and cards manually.
  • Bulk import — scans folders; found programs, files, scripts, and shortcuts become cards.

"Read-Only" and "No storage" modes

Read-Only — the data folder isn't writable. Cards remain visible and launchable, but changes aren't saved to disk and last only until you close the app. That's why settings and Editor changes don't persist in this mode.

No storage — the drive holding the data folder is disconnected (e.g., an ejected USB drive). Changes stay in memory and may be written if the drive returns before you close the app. Closing it earlier loses them.

The "File Corrupted" dialog

The app couldn't read one of its data files. The file is not modified automatically — you choose whether to delete it or keep it. Before deleting a section file, the app automatically copies it to .backup\. If the problem is broader, first save a copy of the whole ErrantLauncher folder.

Running from a USB drive

Supported — data lives next to the executable. Keep in mind:

  • Cards with absolute paths (D:\Tools\app.exe) won't open on a computer lacking that drive letter;
  • Ejecting the drive while running shows the "No storage" status — see above.

A card won't launch

Check in order:

  • "File missing" — the target file isn't at its saved path. Verify the file exists; if the drive letter changed, fix the path in the card.
  • "Media missing" — the drive with the target isn't connected. Reconnect and retry.
  • "Error" badge — launch failed. Causes: deleted file, insufficient rights, antivirus block, invalid command. Check the log for details.
  • Error requesting elevation — running as administrator requires a UAC confirmation. Declining it simply cancels the launch — not an error;
  • Command or link won't open — check the command/URL text; Windows opens the browser or app registered for that address type.

A command card leaves a console window

Command cards run through the Windows command processor, and the console window stays open on purpose — so you can review the command's output. Close it manually when you no longer need the results.

Bulk import finished partially or with errors

Before importing, the app creates a backup in .mass-import-backups\ and verifies it with SHA-256. Only the latest verified backup is kept — you can restore it manually with the app closed. Partial results are expected: files filtered out by type, extension, or architecture are not added. See the data documentation for details.

Full Backup vs. Share Collection — what's the difference?

  • Full Backup — everything: sections, icons, settings, state. Named ErrantLauncher-Backup.zip.
  • Share Collection — sections, icons, and favorites, without settings. Named ErrantLauncher-Collection.zip.

Cards or settings disappeared — where is my data?

All data lives in the ErrantLauncher folder next to the executable: sections\*.json (cards), settings.json, custom-icons\. If the app opens "empty," check whether a different executable (or a copy in another folder) is running, or whether Read-Only mode is active.

The window doesn't fit my screen

The window has a fixed size — it cannot be resized. At high Windows scaling on low-resolution displays (e.g., 1366×768 at 150%) it may not fit. Reduce display scaling or use a higher-resolution screen.

"Data was created by a newer version"

The data folder was written by a newer app version. Files are read but not overwritten — to protect their format. Update the application to the current version.

Updating without losing data

There's no auto-update. Close the app, unpack the new ZIP, and replace all application files — the EXE and both DLLs together, not just the EXE. Leave the ErrantLauncher folder untouched — your collection and settings will be preserved. See the update section for details.

Where are the logs, and how do I report a bug?

Logs: ErrantLauncher\logs\app.log and bootstrap.log. Before sending, open them in Notepad and remove anything you don't want to share — paths may contain your folder names. Open an issue on GitHub with: app version (About window), Windows version (winver), reproduction steps, and the error text. Details on the Support page.
