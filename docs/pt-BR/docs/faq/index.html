O aplicativo não inicia

Possíveis causas: versão desatualizada do Windows; arquitetura não suportada; uma instância já em execução; pasta de dados indisponível.

O que verificar:

  1. O Windows deve ser de 64 bits, versão Windows 10 (1607) ou mais recente. Windows 7/8 e sistemas de 32 bits não são suportados.
  2. Olhe a área de notificação (bandeja) — o programa pode já estar em execução minimizado.
  3. Verifique se a pasta ErrantLauncher existe ao lado do exe e se está disponível para leitura.

O que tentar: mova o exe para uma pasta normal em um disco local (por exemplo, C:\Tools\) e execute novamente; verifique o registro ErrantLauncher\logs\bootstrap.log — ele é criado em falhas de inicialização.

Informar ao suporte: a versão do Windows, a localização do exe e o conteúdo do bootstrap.log, se existir.

Aviso do SmartScreen

Causa: o executável não é assinado digitalmente — para uma versão beta isso é esperado, não é sinal de problema.

O que verificar (recomendado): a autenticidade do arquivo pela soma de verificação. No PowerShell, na pasta do programa:

Get-FileHash .\ErrantLauncher-x64.exe -Algorithm SHA256

Compare o resultado com a linha no arquivo SHA256SUMS.txt do pacote de lançamento.

O que fazer: na janela do SmartScreen clique em «Mais informações» → «Executar assim mesmo». Não é necessário nem recomendado desativar o SmartScreen ou outras proteções do Windows.

É preciso ter o .NET instalado?

Não. O runtime do .NET está embutido no executável — o programa funciona em um Windows limpo sem .NET instalado.

Considere a contrapartida da distribuição em arquivo único: a cada execução o programa descompacta as bibliotecas em %TEMP%\.net\ErrantLauncher. Os diretórios se acumulam — podem ser excluídos manualmente com o aplicativo fechado.

«Errant Launcher já está em execução»

Causa: apenas uma instância do programa pode rodar; uma segunda execução exibe esta notificação.

O que verificar: a área de notificação (bandeja) — o programa pode ter sido minimizado para lá; se não for possível contatar a instância em execução, o programa informará isso separadamente.

O que tentar: feche o processo pelo menu da bandeja «Sair» ou pelo Gerenciador de Tarefas e execute novamente.

Modo «Somente leitura» e «Sem mídia»

Causas:

  • Somente leitura — o programa não tem permissão de gravação na pasta de dados (mídia protegida, permissões de acesso, quarentena).
  • Sem mídia — a pasta de dados está temporariamente indisponível (unidade USB desconectada).

O que acontece: no modo somente leitura os cartões podem ser vistos e executados, mas as alterações são rejeitadas com uma mensagem clara. Com «Sem mídia» as alterações ficam na memória e serão salvas após a reconexão da unidade — o programa informará «Unidade reconectada».

O que verificar: se existe a pasta ErrantLauncher ao lado do exe; se ela tem o atributo «somente leitura»; se a unidade com o mesmo conteúdo está conectada.

«Arquivo corrompido»

O que aconteceu: um dos arquivos de dados (por exemplo, de uma seção ou das configurações) não pode ser lido. O programa ignora esse arquivo e não o modifica — o restante dos seus dados está seguro.

O que é oferecido: no diálogo — «Excluir» o arquivo corrompido ou «Manter» (por exemplo, para tentar restaurá-lo manualmente).

O que tentar: restaurar o arquivo a partir de um backup — de um arquivo exportado via «Importar configuração» ou manualmente de .backup\/.mass-import-backups\ dentro da pasta de dados.

Execução a partir de unidade USB

Normal: é um cenário padrão — transporte o exe e a pasta ErrantLauncher juntos.

Problemas típicos:

  • O programa encerrou ao remover — feche-o antes de remover a unidade.
  • Os cartões não executam em outro computador — eles referenciam arquivos por caminhos locais; verifique os status dos cartões e os caminhos.
  • As alterações não são salvas — veja a seção sobre o modo «Somente leitura».

Um cartão-comando deixa uma janela de console

É uma característica, não um erro. Os comandos são executados com cmd /k ou powershell -NoExit para que a saída fique na tela. Feche a janela do console manualmente quando não precisar mais do resultado.

Leve em conta também: os comandos sempre são executados a partir da pasta de dados do programa — os cartões-comando não têm uma pasta de trabalho própria. Se um comando precisar de outra pasta, comece-o com cd /d "caminho" (ou indique o caminho dentro do próprio comando).

O cartão mostra «Arquivo ausente» ou «Mídia ausente»

Causa: o programa verifica a disponibilidade dos alvos dos cartões. Status:

Status Significado
Disponível O alvo foi encontrado
Arquivo ausente Não há arquivo no caminho indicado
Origem indisponível A pasta/origem não pode ser lida
Mídia ausente O disco/unidade não está conectado
Verificando… Verificação em andamento

O que verificar: se o arquivo existe no caminho indicado; se o disco necessário está conectado (especialmente após transportar o launcher para outro computador). O caminho pode ser corrigido em «Editar cartões».

A importação em massa terminou parcialmente ou com erros

Possíveis causas: caminhos e nomes duplicados, arquivos indisponíveis, tipos desativados pelos filtros, limite de candidatos atingido, erros de gravação.

O que verificar: o relatório final da importação lista as razões («duplicado: já existe cartão», «nome já em uso», «sumiu — arquivo não encontrado»). As notas na tela de resultados mostram o que os filtros cortaram: tipos, arquiteturas, extensões, pastas excluídas.

O que tentar: ajustar os filtros e a seleção; usar a «Nova verificação» em vez de uma nova verificação completa.

Se a gravação foi interrompida: antes da importação um backup é criado automaticamente (em .mass-import-backups\). A mensagem de erro indica o caminho dele e a ação: copie o conteúdo sobre a pasta de dados ou repita a importação. Não exclua a pasta de dados manualmente — isso destruiria também os backups.

A janela não cabe na tela

Causa: as janelas do programa têm tamanho fixo (conteúdo 1000 × 620 DIP, tamanho externo 1028 × 648 DIP). Se a área de trabalho da tela for menor — por exemplo, baixa resolução combinada com escala alta do Windows — parte da janela pode sair das bordas da tela, incluindo a barra superior com os botões da janela.

O que verificar: a escala do Windows (Configurações → Sistema → Tela → Escala) e a resolução da tela.

O que tentar: reduzir a escala do Windows ou escolher uma resolução maior; se parte da janela ficar fora da tela — mudar a escala e reiniciar o programa para que a janela se centralize novamente.

Detalhes: Requisitos de sistema.

Atualização e preservação de dados

Atualização: não há atualização automática — substitua o exe com o programa fechado; não toque na pasta ErrantLauncher.

Dados após a atualização: são preservados. Se os arquivos de dados foram criados por uma versão mais nova do programa, a versão antiga os lerá, mas não os modificará — atualize o programa.

Ordenação dos cartões: a ordem de ordenação escolhida é guardada apenas durante a sessão — após reiniciar, aplica-se a ordem padrão. É uma limitação conhecida da beta, não perda de dados.

Onde encontrar os registros e como reportar um erro

Registros: ErrantLauncher\logs\ ao lado do exe — app.log (mensagens de trabalho e erros) e bootstrap.log (falhas de inicialização). Os registros não são enviados a lugar nenhum automaticamente.

Como reportar um erro: instruções passo a passo, o que anexar e onde escrever — no documento Suporte e relatos de erros.

Atenção

Antes de enviar um registro, revise-o: ele pode conter caminhos dos seus arquivos e pastas.
