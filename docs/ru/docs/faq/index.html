Приложение не запускается

Возможные причины: устаревшая версия Windows; неподдерживаемая архитектура; уже запущенный экземпляр; недоступная папка данных.

Что проверить:

  1. Windows должна быть 64-разрядной, версии Windows 10 (1607) или новее. Windows 7/8 и 32-разрядные системы не поддерживаются.
  2. Посмотрите в область уведомлений (трей) — программа может быть уже запущена и свёрнута.
  3. Проверьте, существует ли папка ErrantLauncher рядом с exe и доступна ли она для чтения.

Что попробовать: переместите exe-файл в обычную папку на локальном диске (например, C:\Tools\) и запустите снова; проверьте журнал ErrantLauncher\logs\bootstrap.log — он создаётся при сбоях запуска.

Сообщить поддержке: версию Windows, расположение exe-файла и содержимое bootstrap.log, если он есть.

Предупреждение SmartScreen

Причина: исполняемый файл не подписан цифровой подписью — для бета-версии это ожидаемо, это не признак проблемы.

Что проверить (рекомендуется): подлинность файла по контрольной сумме. В PowerShell в папке с программой:

Get-FileHash .\ErrantLauncher-x64.exe -Algorithm SHA256

Сравните результат со строкой в файле SHA256SUMS.txt из комплекта релиза.

Что сделать: в окне SmartScreen нажмите «Подробнее» → «Выполнить в любом случае». Отключать SmartScreen или другую защиту Windows не требуется и не рекомендуется.

Нужен ли установленный .NET

Нет. Среда выполнения .NET встроена в исполняемый файл — программа работает на чистой Windows без установленного .NET.

Учтите обратную сторону однофайловой поставки: при каждом запуске программа распаковывает библиотеки в %TEMP%\.net\ErrantLauncher. Каталоги накапливаются — их можно удалить вручную, пока приложение закрыто.

«Errant Launcher уже запущен»

Причина: работает только один экземпляр программы; второй запуск выводит это уведомление.

Что проверить: область уведомлений (трей) — программа могла сворачиваться туда; если связаться с запущенным экземпляром не удаётся, программа сообщит об этом отдельно.

Что попробовать: закройте процесс через меню трея «Выход» или диспетчер задач и запустите снова.

Режим «Только чтение» и «Нет носителя»

Причины:

  • Только чтение — у программы нет прав на запись в папку данных (защищённый носитель, права доступа, карантин).
  • Нет носителя — папка данных временно недоступна (отключён USB-накопитель).

Что происходит: в режиме только чтения карточки можно смотреть и запускать, но изменения отклоняются с понятным сообщением. При «Нет носителя» изменения остаются в памяти и сохранятся после повторного подключения накопителя — программа сообщит «Накопитель снова подключён».

Что проверить: есть ли папка ErrantLauncher рядом с exe; не установлен ли у неё атрибут «только чтение»; подключён ли накопитель с тем же содержимым.

«Файл повреждён»

Что произошло: один из файлов данных (например, раздела или настроек) не читается. Программа игнорирует такой файл и не изменяет его — ваши остальные данные в безопасности.

Что предлагается: в диалоге — «Удалить» повреждённый файл или «Оставить» его (например, чтобы попытаться восстановить вручную).

Что попробовать: восстановить файл из резервной копии — из экспортированного архива через «Импорт конфигурации» или вручную из .backup\/.mass-import-backups\ внутри папки данных.

Запуск с USB-накопителя

Нормально: это штатный сценарий — переносите exe и папку ErrantLauncher вместе.

Типичные проблемы:

  • Программа завершилась при извлечении — закрывайте её до извлечения накопителя.
  • Карточки не запускаются на другом компьютере — они ссылаются на файлы по локальным путям; проверьте статусы карточек и пути.
  • Изменения не сохраняются — смотрите раздел про режим «Только чтение».

Карточка-команда оставляет окно консоли

Это особенность, а не ошибка. Команды выполняются с cmd /k или powershell -NoExit, чтобы вывод остался на экране. Закройте окно консоли вручную, когда результат больше не нужен.

Учтите также: команды всегда выполняются из папки данных программы — отдельной рабочей папки у карточек-команд нет. Если команде нужна другая папка, начните её с cd /d "путь" (или укажите путь в самой команде).

Карточка показывает «Файл отсутствует» или «Носитель отсутствует»

Причина: программа проверяет доступность целей карточек. Статусы:

Статус Значение
Доступно Цель найдена
Файл отсутствует Файла нет по указанному пути
Источник недоступен Папка/источник не читается
Носитель отсутствует Диск/накопитель не подключён
Проверка… Идёт проверка

Что проверить: существует ли файл по указанному пути; подключён ли нужный диск (особенно после переноса лаунчера на другой компьютер). Исправить путь можно в «Редактировать карточки».

Массовый импорт завершился частично или с ошибками

Возможные причины: дубликаты путей и имён, недоступные файлы, отключённые фильтрами типы, достигнутый лимит кандидатов, ошибки записи.

Что проверить: итоговый отчёт импорта перечисляет причины («дубликат: уже есть карта», «имя уже используется», «пропал — файл не найден»). Заметки на экране результатов показывают, что отсекли фильтры: типы, архитектуры, расширения, исключённые папки.

Что попробовать: скорректировать фильтры и выбор; использовать «Повторную проверку» вместо нового сканирования.

Если запись прервалась: перед импортом автоматически создаётся резервная копия (в .mass-import-backups\). Сообщение об ошибке указывает путь к ней и действие: скопируйте её содержимое поверх папки данных или повторите импорт. Не удаляйте папку данных вручную — это уничтожит и резервные копии.

Окно не помещается на экране

Причина: окна программы имеют фиксированный размер (содержимое 1000 × 620 DIP, внешний габарит 1028 × 648 DIP). Если рабочая область экрана меньше — например, при низком разрешении в сочетании с высоким масштабом Windows — часть окна может уйти за края экрана, включая верхнюю панель с кнопками окна.

Что проверить: масштаб Windows (Параметры → Система → Дисплей → Масштаб) и разрешение экрана.

Что попробовать: уменьшить масштаб Windows или выбрать более высокое разрешение; если часть окна за экраном — изменить масштаб и перезапустить программу, чтобы окно отцентрировалось заново.

Подробности: Системные требования.

Обновление и сохранение данных

Обновление: автообновления нет — замените exe-файл при закрытой программе; папку ErrantLauncher не трогайте.

Данные после обновления: сохраняются. Если файлы данных созданы более новой версией программы, старая версия прочитает их, но не будет изменять — обновите программу.

Сортировка карточек: выбранный порядок сортировки хранится только на время сессии — после перезапуска применяется порядок по умолчанию. Это известное ограничение беты, а не потеря данных.

Где искать журналы и как сообщить об ошибке

Журналы: ErrantLauncher\logs\ рядом с exe — app.log (рабочие сообщения и ошибки) и bootstrap.log (сбои запуска). Журналы никуда не отправляются автоматически.

Как сообщить об ошибке: пошаговая инструкция, что приложить и куда писать — в документе Поддержка и отчёты об ошибках.

Внимание

Перед отправкой журнала просмотрите его: в нём могут быть пути к вашим файлам и папкам.
